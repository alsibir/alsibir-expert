Подсистема Windows для Linux (WSL) позволяет запускать Linux-программы в Windows без отдельного сеанса полноценной виртуальной машины. В современных конфигурациях WSL 2 графические приложения Linux могут открываться в обычных окнах Windows благодаря WSLg.

В архивной инструкции 2019 года предлагается установить Ubuntu 18.04, полноценный рабочий стол GNOME и отдельный X-сервер VcXsrv. Для современных версий Windows этот порядок не является базовым: он сложнее, а часть действий не нужна. Ниже приведён актуальный способ.

## Какие версии Windows поддерживаются

Для описанной установки WSL используются Windows 10 версии 2004 (сборка 19041) и новее либо Windows 11. Для встроенной поддержки графических приложений WSLg требуется Windows 10 **сборки 19044 и выше** либо Windows 11, а также WSL 2.

Проверить версию Windows можно командой `winver` через окно «Выполнить» (`Win + R`). На корпоративном компьютере установка WSL может быть ограничена политикой администратора.

## Шаг 1. Установить WSL

Запустить PowerShell от имени администратора:

```powershell
wsl --install
```

При необходимости перезагрузить Windows. Эта команда устанавливает необходимые компоненты и, если не выбран другой дистрибутив, Ubuntu. На системах с уже установленной WSL поведение команды может отличаться; перечень доступных дистрибутивов отображается так:

```powershell
wsl --list --online
```

Для установки выбранного дистрибутива можно использовать:

```powershell
wsl --install -d Ubuntu
```

При первом запуске Ubuntu потребуется создать пользователя Linux и пароль для команд `sudo`.

## Шаг 2. Проверить WSL 2 и установить обновления

В PowerShell:

```powershell
wsl --list --verbose
wsl --update
```

В выводе `wsl --list --verbose` для дистрибутива должна быть указана версия `2`. Если используется WSL 1, графический режим WSLg в этой конфигурации недоступен. Перед изменением версии рекомендуется ознакомиться с требованиями Microsoft и сохранить важные данные.

## Шаг 3. Установить приложение Linux с интерфейсом

Открыть терминал Ubuntu и обновить сведения о пакетах:

```bash
sudo apt update
```

Для проверки графического режима можно установить простые X11-приложения:

```bash
sudo apt install x11-apps
```

Затем запустить:

```bash
xclock
```

При работающем WSLg появится отдельное окно с часами на рабочем столе Windows. После проверки приложение можно закрыть обычным способом.

## Шаг 4. Открыть файлы Linux из Windows

Самый удобный способ — в Проводнике Windows использовать сетевой путь:

```text
\\wsl$\Ubuntu\home\
```

Имя `Ubuntu` нужно заменить именем установленного дистрибутива, если оно отличается. Из терминала WSL текущую папку удобно открыть командой:

```bash
explorer.exe .
```

**Не следует вручную редактировать виртуальный диск или внутренние файлы Linux-дистрибутива в служебных папках Windows.** Используйте поддерживаемые способы доступа `\\wsl$` и инструменты WSL.

## Почему не нужно устанавливать целый GNOME

WSLg предназначен прежде всего для отдельных графических приложений, а не для замены рабочего стола Windows полноценной сессией GNOME. Установка пакета `ubuntu-desktop` значительно увеличивает число зависимостей и может привести к конфликтам служб, сеансов и способов запуска интерфейса.

Если необходим **полный рабочий стол Linux**, чаще целесообразно выбрать виртуальную машину или отдельную установку Linux. В WSL в большинстве практических задач достаточно отдельных редакторов, визуализаторов и служебных программ.

## Типичные проблемы и способы решения

### Команда wsl не выполняется

Проверьте сборку Windows, полномочия, доступность виртуализации, наличие обновлений и состояние компонентов WSL. Пошаговая диагностика приведена в [инструкции Microsoft](https://learn.microsoft.com/ru-ru/windows/wsl/install).

### Программа запускается, но окно не появляется

Убедитесь, что используется WSL 2, поддерживается WSLg и выполнена команда `wsl --update`. Полезно завершить запущенные дистрибутивы через PowerShell и запустить Ubuntu заново:

```powershell
wsl --shutdown
```

Команда завершает все текущие сеансы WSL. Сначала сохраните несохранённые данные в Linux-приложениях.

### Приложение не видит графический ускоритель

Для аппаратного ускорения может потребоваться совместимый драйвер GPU. Без него некоторые приложения работают медленнее или используют программную обработку. Сведения о поддерживаемых конфигурациях приведены в документации WSLg.

## Итог

Для Windows 10 поздних сборок и Windows 11 разумно начинать с WSL 2 и WSLg: установить WSL, обновить компоненты и запустить нужную графическую программу. Схему с отдельным X-сервером и полноэкранным GNOME следует рассматривать только как специальный сценарий, когда он действительно необходим.
