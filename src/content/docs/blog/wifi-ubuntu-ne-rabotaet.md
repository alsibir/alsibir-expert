После установки Ubuntu беспроводная сеть иногда не появляется в списке, подключение обрывается или система не видит адаптер. Причина может заключаться в выключенном радиомодуле, драйвере, прошивке устройства, настройках NetworkManager или самом маршрутизаторе.

Начинать рекомендуется с проверок, которые **не изменяют конфигурацию системы**. Не следует сразу устанавливать случайные драйверы из Интернета или выполнять команды из старых инструкций для Ubuntu 7.04–7.10.

## Шаг 1. Проверить Wi-Fi в графических настройках

1. Открыть меню сети или раздел «Настройки» → «Wi-Fi».
2. Убедиться, что беспроводная сеть включена и отключён режим полёта.
3. Проверить, видны ли другие сети.
4. Перезапустить беспроводной маршрутизатор только при наличии оснований: например, если эта сеть не видна ни одному устройству.

Если сети есть, но не удаётся подключиться к одной конкретной точке доступа, сначала проверить пароль, метод защиты и настройки маршрутизатора. Если список пуст или отсутствует сам переключатель Wi-Fi — перейти к диагностике адаптера.

## Шаг 2. Узнать, видит ли Ubuntu сетевой адаптер

Открыть терминал и выполнить:

```bash
nmcli device status
```

Команда показывает список интерфейсов и их состояние. Тип `wifi` означает, что NetworkManager видит беспроводной интерфейс.

Для проверки адаптера PCIe:

```bash
lspci -nnk | grep -A 4 -i 'network controller'
```

Для USB-адаптера:

```bash
lsusb
```

В некоторых системах название устройства отличается от `wlan0`: возможны обозначения `wlp2s0`, `wlan1` и другие. Команды в инструкции не требуют конкретного имени интерфейса, пока это не указано отдельно.

## Шаг 3. Проверить аппаратную блокировку

Выполнить:

```bash
rfkill list
```

Если для беспроводного адаптера указано `Soft blocked: yes`, можно попробовать снять программную блокировку:

```bash
sudo rfkill unblock wifi
```

Если отображается `Hard blocked: yes`, необходимо проверить физический переключатель, сочетание клавиш ноутбука или настройки прошивки. Программная команда не снимает аппаратную блокировку.

## Шаг 4. Включить Wi-Fi и обновить список сетей

При использовании NetworkManager выполнить:

```bash
nmcli radio wifi on
nmcli device wifi rescan
nmcli device wifi list
```

Если нужная сеть появилась, подключиться можно через графический интерфейс. В терминале удобнее использовать интерактивный запрос пароля:

```bash
nmcli --ask device wifi connect 'ИМЯ_СЕТИ'
```

Вместо `ИМЯ_СЕТИ` нужно указать реальный идентификатор сети. Такой способ позволяет не записывать пароль непосредственно в историю команд оболочки.

## Шаг 5. Проверить драйвер и прошивку адаптера

Когда система определяет оборудование, но беспроводной интерфейс не работает, необходимо выяснить точную модель чипсета и используемый драйвер. Для PCIe-устройств это видно в выводе `lspci -nnk` в строке `Kernel driver in use`.

Рекомендуется:

1. Уточнить модель адаптера и версию Ubuntu.
2. Проверить раздел «Программы и обновления» → «Дополнительные драйверы», если он доступен.
3. Установить предложенный совместимый драйвер из доверенного репозитория.
4. Перезагрузить компьютер и повторить проверку состояния.

Для некоторых адаптеров требуется отдельная прошивка. Конкретный пакет нельзя выбирать только по торговому названию ноутбука: разные ревизии могут иметь разные чипсеты.

## Шаг 6. Посмотреть журнал NetworkManager

Если предыдущие проверки не помогли:

```bash
journalctl -b -u NetworkManager --no-pager | tail -n 80
```

Команда показывает недавние сообщения службы в пределах текущей загрузки. Ищите упоминания отсутствующей прошивки, ошибок аутентификации и невозможности активировать интерфейс. Если NetworkManager не используется, диагностировать нужно фактический сетевой менеджер системы.

Также полезно проверить блокировку устройства:

```bash
ip link show
```

Само наличие интерфейса в этом выводе ещё не доказывает, что сеть и драйвер работают корректно.

## Чего не делать по старым инструкциям

Материал 2008 года из исходного архива описывает адаптеры Atheros, Broadcom и D-Link, работу с `ndiswrapper`, старые версии Ubuntu и ручное внесение строк `blacklist ath_pci`. Эти действия относятся к конкретным устаревшим драйверам и **не являются универсальным способом исправления Wi-Fi в современных системах**.

Не следует наугад изменять файлы `/etc/modprobe.d/`, отключать модули ядра и использовать случайные Windows-драйверы. Это способно полностью отключить действующий сетевой адаптер.

## Таблица быстрой диагностики

| Симптом | С чего начать |
| --- | --- |
| Нет переключателя Wi-Fi | `nmcli device status`, `lspci`, `lsusb` |
| Адаптер есть, но отключён | `rfkill list`, проверка режима полёта |
| Не показываются точки доступа | `nmcli device wifi rescan`, проверка драйвера |
| Сеть видна, пароль не принимается | Тип защиты, пароль, настройки маршрутизатора |
| Периодические отключения | Журналы службы, энергосбережение, уровень сигнала |

## Итог

В большинстве случаев последовательная диагностика экономит время: сначала определить устройство, затем проверить блокировку и NetworkManager, после чего переходить к драйверу и журналам. Решение должно соответствовать конкретной модели адаптера и используемой версии Linux.
