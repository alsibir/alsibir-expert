![Подготовка базы знаний с диаграммами, формулами и кодом](/alsibir-expert/images/articles/confluence-tools.png)

В рабочей базе знаний нужны диаграммы, формулы, фрагменты кода, понятная навигация и выпуск документации в PDF. Часть задач решается штатными средствами Confluence, часть — установленными приложениями. Набор следует выбирать по задачам и версии платформы.

Исходный рабочий список включал Countdown, LaTeX, JSON Viewer Macro, draw.io и Roadmap; отдельно рассматривались Markdown, встроенный код, HTML, iframe, PDF и проверка ссылок. Этот перечень отражает использовавшуюся среду и потребности Автора. Названия без поставщика и идентификатора приложения не позволяют подтвердить конкретную редакцию или текущую установку.

## Сначала определите среду

Confluence Cloud и Confluence Data Center различаются редактором, доступными макросами и способом установки приложений. Совпадающее название не гарантирует переносимость страницы между ними.

Перед выбором расширения фиксируются тип размещения, версия Confluence, поставщик, идентификатор Marketplace, лицензия и поддерживаемые версии. Для ранее установленных приложений дополнительно проверяется сохранность страниц после обновления или удаления.

## Какие средства нужны для повседневной работы

| Задача | Средство или способ | Что требуется проверить |
| --- | --- | --- |
| Диаграммы | draw.io | Редактирование исходника, права, экспорт в PDF |
| Формулы | Приложение с поддержкой LaTeX | Точный поставщик, поддерживаемый синтаксис, экспорт |
| Структурированные данные | JSON Viewer Macro | Возможность поиска, сворачивания и скрытия чувствительных полей |
| Обратный отсчёт | Countdown | Источник даты, часовой пояс, поведение после истечения срока |
| План работ | Roadmap или доступный штатный макрос | Соответствие среде и актуальность плана |
| Код внутри абзаца | Штатное оформление кода | Возможности используемого редактора |
| Markdown | Преобразование разметки или специальный макрос | Сохраняется ли редактируемый исходный Markdown |
| Навигация по темам | Метки, списки материалов, облако меток | Единый словарь и работа без приложения |
| Проверка ссылок | Link Error Report и дополнительные проверки | Охват внутренних и внешних адресов |

Для Countdown, LaTeX, JSON Viewer Macro и Roadmap названия в исходном перечне недостаточны для рекомендации конкретного приложения. Подбор выполняется по карточке установленного компонента, а не по сходству названий в поиске.

## Bootstrap Visuals и TagCloud: что изменилось

Bootstrap Visuals for Confluence от Lewe использовался для визуальных объектов: уведомлений, кнопок, значков и индикаторов. Сейчас [карточка приложения находится в архиве Marketplace](https://marketplace.atlassian.com/archive/1217910). Старую отметку «поддерживается разработчиком» нельзя считать актуальным основанием для новой установки.

Для новой базы знаний следует сначала рассмотреть штатные панели и информационные блоки. Если требуется расширение оформления, оно должно явно поддерживать используемую платформу. Перед отказом от старого приложения нужно определить страницы с его макросами и способ сохранения содержимого.

В исходном списке TagCloud for Confluence от Siemens AG, Corporate Technology был отмечен как неподдерживаемый. Перед публикацией требований к новой среде необходимо уточнить точный идентификатор и статус. Одноимённые приложения других поставщиков нельзя автоматически считать его продолжением. Базовый запасной вариант — согласованные метки и страницы-каталоги.

## Markdown: преобразование или сохранение исходника

Это две разные задачи. Вставка Markdown с преобразованием в формат редактора позволяет быстро перенести текст, но не гарантирует дальнейшее редактирование в исходной разметке. Например, [документация Data Center](https://confluence.atlassian.com/conf94/confluence-wiki-markup-1540721807.html) прямо описывает такое преобразование.

Если требуется хранить и обновлять исходный Markdown, нужен соответствующий макрос или интеграция. Ранее указанное приложение Markdown Macro for Confluence от Atlas Authority следует идентифицировать по карточке Marketplace: приложение с [идентификатором 1211438](https://marketplace.atlassian.com/apps/1211438/markdown-macro-for-confluence) теперь представлено под названием Just Add+ и поставщиком Modus Create.

До внедрения проверьте таблицы, ссылки, изображения, блоки кода и экспорт. Для подключения материалов из репозитория отдельно задаются разрешённые источники и доступ к закрытым данным.

## Код внутри строки: отдельный плагин обычно не нужен

В актуальном редакторе Confluence Cloud короткий фрагмент оформляется обратными кавычками: `config.yaml`. Для многострочного примера используется блок кода. Эти возможности описаны в [справке Atlassian](https://support.atlassian.com/confluence-cloud/docs/insert-elements-into-a-page/).

Поэтому старые рекомендации по самостоятельному добавлению Inline Code следует применять только к конкретной старой среде после проверки штатных средств. Наличие моноширинного текста и наличие подсветки синтаксиса внутри строки — разные требования.

## HTML и iframe

В Data Center HTML Macro относится к наследуемым возможностям и по умолчанию отключён. [Atlassian предупреждает](https://confluence.atlassian.com/doc/html-macro-38273085.html), что его включение может создавать риск выполнения нежелательного кода на страницах. Возможность управляется администратором; инструкции для Data Center не переносятся на Cloud.

Для внешнего содержимого предпочтительно сначала проверить штатное встраивание или поддерживаемое приложение. Даже корректный iframe не гарантирует показ: внешний сайт может запрещать встраивание, требовать отдельную авторизацию или быть недоступным из сети читателя.

На странице следует оставить обычную ссылку и краткое описание внешнего материала. Это помогает при блокировке встраивания и выпуске PDF, где интерактивное содержимое может отсутствовать. Не следует вставлять в HTML или iframe секреты доступа.

## Экспорт в PDF и русские шрифты

Сначала экспортируйте контрольную страницу с кириллицей, таблицей, кодом, формулой и диаграммой. Проверяйте не только отображение, но и поиск, копирование текста, переносы строк и обрезанные элементы.

В Confluence Cloud обновлённый механизм экспорта во многих случаях использует языки без отдельной установки шрифта. Для старого механизма и отдельных вариантов экспорта может потребоваться [загрузка пользовательского шрифта](https://support.atlassian.com/confluence-cloud/docs/create-pdf-using-custom-font/). Поэтому совет «обязательно установить русский шрифт» не является универсальным.

Для Data Center действует [собственная процедура](https://confluence.atlassian.com/conf101/create-a-pdf-in-another-language-1652924552.html) с TTF/TTC и настройкой шрифта экспорта. Перед заменой проверяются охват нужных символов, права использования шрифта и влияние на другие пространства.

## Контроль битых ссылок

[Link Error Report for Confluence от Hivestone](https://marketplace.atlassian.com/apps/1217422/link-error-report-for-confluence) формирует отчёт по внутренним ссылкам на пространства, страницы и якоря. По описанию поставщика, внешние веб-адреса приложение не проверяет.

Таким образом, для полного контроля нужны две процедуры: проверка внутренних переходов и отдельная проверка внешних адресов. Недоступность ссылки также может быть следствием ограничений прав, а не удаления страницы. Проверку полезно выполнять с ролью обычного читателя.

## Задачи Jira и списки дел

Список todo сам по себе не определяет конкретное приложение Jira. Для личной заметки подходит простой список; для управляемой работы нужны задача, ответственный, срок, статус и история изменений. Если требуется связь с документацией, в задаче указывается страница, а на странице — задача.

Выбор стороннего приложения требуется только при отсутствии нужного поведения в штатной конфигурации Jira. Название и поставщик должны быть зафиксированы отдельно.

## Проверка перед внедрением

1. Создайте тестовое пространство и контрольную страницу с нужными типами содержимого.
2. Проверьте чтение и редактирование с разными ролями.
3. Проверьте экспорт и перенос содержимого.
4. Определите поведение при отсутствии лицензии или приложения по документации поставщика либо на тестовой копии.
5. Назначьте владельца настройки и порядок повторной проверки после обновлений.

Хороший набор расширений покрывает необходимые задачи и позволяет сопровождать материалы без зависимости от неподтверждённых или случайно выбранных компонентов.

Сведения по официальным страницам проверены 5 ноября 2026 года. Конкретная рабочая установка Confluence и Jira не обследовалась.
