Neovim — редактор текста и программного кода, который можно превратить в компактную рабочую среду под собственные задачи. Его главное достоинство не в том, что он заменяет все IDE, а в сочетании клавиатурного управления, расширяемости и возможности хранить настройки в обычных текстовых файлах.

В этом руководстве разберём базовый путь: установка, первые команды, конфигурация, плагины и готовые сборки. Отдельно посмотрим, чем Neovim может быть полезен при подготовке технической документации.

## 1. От Vi к Neovim

Семейство редакторов началось с Vi, затем появился Vim — расширенный редактор с настройками и скриптами. Neovim развивает этот подход: сохраняет привычную модель редактирования и добавляет удобные возможности интеграции и конфигурирования, в том числе с использованием Lua.

**Важное отличие от типичной IDE:** после установки Neovim не обязан выглядеть как полноценная среда разработки. Дополнительные функции подключаются по мере необходимости.

## 2. Когда Neovim удобен

- **Редактирование без постоянного обращения к мыши.** Перемещение, выделение и изменение текста выполняются командами.
- **Работа в терминале.** Редактор удобно использовать на локальной машине и при подключении к удалённым системам.
- **Гибкая настройка.** Можно выбрать собственные сочетания клавиш, форматирование и набор расширений.
- **Работа с проектами.** Плагины добавляют дерево файлов, поиск, подсветку, Git-инструменты и языковые серверы.
- **Повторяемая конфигурация.** Настройки можно хранить в системе контроля версий и переносить между компьютерами.

При этом освоение режимов и команд требует времени. Для задач, где критичны визуальная вёрстка и оформление документа в формате Word, Neovim не заменяет специализированный текстовый процессор.

## 3. Установка

Выберите команду для своей системы:

```bash
# macOS с Homebrew
brew install neovim

# Arch Linux
sudo pacman -S neovim

# Debian / Ubuntu
sudo apt-get update
sudo apt-get install neovim

# Fedora
sudo dnf install neovim
```

Проверьте установленную версию:

```bash
nvim --version
```

Запустите редактор:

```bash
nvim
```

Для знакомства с командами воспользуйтесь встроенным обучением:

```vim
:Tutor
```

**Примечание.** Версия пакета в репозитории дистрибутива может отставать от актуальной. Требования к версии Neovim проверяйте отдельно для выбранной сборки и плагинов.

## 4. Режимы работы и основные команды

Neovim использует несколько режимов. В **Normal** выполняют действия над текстом, в **Insert** вводят текст, в **Visual** выделяют фрагменты, а командная строка после `:` позволяет сохранить файл или изменить параметры.

| Действие | Команда |
|---|---|
| Перейти в режим ввода | `i` |
| Начать ввод после курсора | `a` |
| Вернуться в Normal | `Esc` |
| Переместить курсор | `h`, `j`, `k`, `l` |
| Выделить текст | `v` |
| Найти текст | `/строка` |
| Сохранить файл | `:w` |
| Выйти | `:q` |
| Сохранить и выйти | `:wq` |
| Выйти без сохранения | `:q!` |

Большинство буквенных команд рассчитано на английскую раскладку клавиатуры.

## 5. Минимальная конфигурация

В статье-источнике используется файл `init.vim`. На Linux и macOS его обычно размещают по пути `~/.config/nvim/init.vim`. Для Windows путь к конфигурации обычно находится внутри `%LOCALAPPDATA%\nvim`.

Создайте каталог и файл конфигурации:

```bash
mkdir -p ~/.config/nvim
nvim ~/.config/nvim/init.vim
```

Пример настроек на Vimscript:

```vim
" Разрешить работу мышью
set mouse=a

" Показывать номера строк
set number
set relativenumber

" Настройка отступов
set smarttab
set tabstop=2
set shiftwidth=2
set softtabstop=2
set expandtab
set autoindent
```

Здесь `tabstop` задаёт отображаемую ширину символа табуляции, `shiftwidth` — шаг изменения отступа, `softtabstop` — поведение клавиш ввода отступов. `expandtab` позволяет использовать пробелы вместо символов табуляции.

В новых конфигурациях также часто применяют `init.lua`; это альтернативный формат, а не обязательное продолжение `init.vim`.

## 6. Расширение редактора плагинами

Исходный материал демонстрирует менеджер **vim-plug**. Его конфигурация в `init.vim` может выглядеть так:

```vim
call plug#begin()
Plug 'vim-airline/vim-airline'
Plug 'preservim/nerdtree'
Plug 'ryanoasis/vim-devicons'
call plug#end()
```

После установки самого менеджера и добавления этих строк плагины устанавливаются командой:

```vim
:PlugInstall
```

Для открытия дерева файлов можно назначить сочетание клавиш:

```vim
nnoremap <C-n> :NERDTreeToggle<CR>
```

**Назначение расширений:** `vim-airline` выводит информационную строку; `NERDTree` показывает дерево каталогов; `vim-devicons` добавляет значки типов файлов. Для корректного отображения некоторых значков потребуется шрифт с подходящими глифами, например Nerd Font.

Этот пример сохраняет логику исходной статьи. Для новой конфигурации также стоит рассмотреть современные Lua-ориентированные менеджеры плагинов, но не смешивать инструкции разных менеджеров в одном конфиге без необходимости.

## 7. Как превратить редактор в IDE

Один из способов не собирать окружение вручную — использовать готовую конфигурацию. В источнике рассматривается **AstroNvim** и упоминаются альтернативы: **LunarVim**, **NvChad**, **LazyVim**.

Типичная расширенная конфигурация предоставляет:

- автодополнение и подсказки языковых серверов (LSP);
- подсветку синтаксиса и структурный разбор кода;
- поиск по файлам и проекту;
- интеграцию с Git;
- запуск форматтеров и средств статического анализа.

Перед установкой готовой сборки сохраните существующую конфигурацию и данные Neovim. Например, в Linux:

```bash
mv ~/.config/nvim ~/.config/nvim.bak
mv ~/.local/share/nvim ~/.local/share/nvim.bak
```

Эти команды предназначены **только для случая, когда соответствующие каталоги уже существуют**. В исходной публикации приведены команды установки AstroNvim и языковых компонентов, актуальные для её времени. Поскольку структура готовых конфигураций и команды управления плагинами меняются, установку выполняйте по [действующей документации AstroNvim](https://docs.astronvim.com/), а не по старой последовательности команд.

В качестве дополнительных инструментов в источнике перечислены Node.js, Python, ripgrep, lazygit, bottom, gdu и Tree-sitter CLI. Их необходимость зависит от конкретной сборки и набора функций.

## 8. Neovim для технического писателя

В работе над документацией редактор особенно полезен там, где результатом служат **текстовые исходники**, а не визуально оформленный документ:

- **Markdown:** статьи, README, руководства, заметки и документы для статических сайтов.
- **JSON, YAML, XML:** примеры API, конфигурации, структуры данных и служебные файлы.
- **PlantUML и другие текстовые описания диаграмм:** редактирование исходников схем в одном проекте с документацией.
- **Git:** контроль изменений в документах, просмотр истории и совместная работа.
- **Автоматизация:** пакетная обработка текстов, форматирование и проверки через внешние команды и скрипты.

Для сложных ГОСТ-документов с титульными листами, таблицами, стилями и печатной компоновкой Neovim разумно рассматривать как **дополнительный инструмент** для работы с исходными текстами, скриптами и конфигурациями, а не как полноценную замену Word или системы документирования.

## 9. Практический план освоения

1. Установить Neovim и пройти `:Tutor`.
2. Научиться открывать, изменять, сохранять и искать текст.
3. Создать минимальный `init.vim` или `init.lua`.
4. Добавить только действительно нужные плагины.
5. Подключить поиск по проекту, Git и средства работы с используемыми языками.
6. Сохранить рабочую конфигурацию в репозитории, чтобы её можно было воспроизвести.

## Заключение

Neovim особенно хорош для специалистов, которые много работают с текстовыми форматами, исходным кодом и повторяемыми операциями. Его преимущества проявляются после освоения клавиатурной модели и аккуратной настройки под реальные задачи. Начинать лучше с небольшого набора команд и расширять окружение постепенно.
