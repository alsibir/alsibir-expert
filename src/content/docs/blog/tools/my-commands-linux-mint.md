Проверить синхронизацию Яндекс.Диска, подключить VPN, посмотреть свободное место и собрать сайт — для каждой задачи обычно требуется отдельная команда. Если операции повторяются, их удобно собрать в одном меню с понятными названиями и журналом результатов.

«Мои команды» — пользовательский скрипт для Linux Mint с графическим выбором действий. Основная логика написана на Bash, главное окно использует Python и GTK, подменю — Zenity. Операции, требующие просмотра вывода или ввода пароля, выполняются в отдельном терминале.

В статье рассматривается версия **3.0.0**. Диагностика Яндекс.Диска и сценарии управления сайтом включены непосредственно в `menu.sh`. Установочный комплект выполняет только чистую установку. Если прежняя версия присутствует, она целиком сохраняется на рабочем столе и удаляется из рабочего расположения переносом. Файлы нового комплекта устанавливаются в отдельный чистый каталог; старые настройки не переносятся.

## Скачать скрипт и инструкцию

- [Установочный комплект «Мои команды» 3.0.0](/alsibir-expert/downloads/my-commands/my-commands-v3.0.0.tar.gz).
- [Инструкция по установке, проверке и восстановлению](/alsibir-expert/downloads/my-commands/my-commands-installation.md).

Архив содержит `menu.sh`, установщик `install.sh`, значок `menu-icon.svg` и инструкцию `README.md`. Проект сайта, Node.js, клиент Яндекс.Диска и AdGuard VPN устанавливаются отдельно.

## Какие задачи доступны

| Раздел | Основные возможности |
| --- | --- |
| AdGuard VPN | Первый раздел: статус, расширенная диагностика, подключение и отключение, выбор направления, вывод доступных локаций |
| Яндекс.Диск | Статус, запуск, остановка, перезапуск, проверка процессов и cpulimit, полная диагностика, работа с отчётами |
| Диски и файловые системы | Список накопителей и разделов, свободное место, точки монтирования, inode, UUID и типы файловых систем |
| Сайт АПС | Проверка окружения, синхронизация рабочей копии, локальный сервер, сборка, просмотр результата и резервные копии |
| Система | Память, время работы, активные процессы, ошибки загрузки, операции APT, перезагрузка и выключение |
| Журналы | Последние записи, просмотр полного журнала, открытие каталогов и очистка общего журнала |

Меню обращается к установленным системным программам. Оно упрощает их запуск и собирает результаты, но не заменяет сами клиенты и службы.

## Что изменилось в версии 3.0.0

1. AdGuard VPN перенесён на первое место главного меню.
2. После команды возвращается подменю текущего раздела: несколько действий можно выполнять подряд.
3. Исключено обновление поверх старой установки. Прежние файлы сохраняются на рабочем столе, после чего устанавливается чистый комплект.

## Установка

### 1. Подготовить окружение

Установщик проверяет наличие `zenity`, `x-terminal-emulator`, `tee`, `mktemp`, Python, библиотеки GTK для Python и `xdg-user-dir`. Если проверка сообщает об отсутствующих графических компонентах, предусмотрена команда:

```bash
sudo apt install python3-gi gir1.2-gtk-3.0 zenity xdg-user-dirs
```

Остальные недостающие компоненты необходимо установить по сообщениям проверки. Для команд отдельных разделов нужны соответствующие приложения: например, `adguardvpn-cli` для VPN и клиент Яндекс.Диска для синхронизации. Наличие всех программ для всех операций установщик не проверяет.

### 2. Распаковать комплект

Скачать установочный архив и распаковать его через файловый менеджер. Открыть каталог `my-commands-v3` в терминале.

Если архив находится в текущем каталоге, можно выполнить:

```bash
tar -xzf my-commands-v3.0.0.tar.gz
cd my-commands-v3
```

### 3. Выполнить установку

Закрыть ранее запущенное меню и терминалы его операций. Выполнить:

```bash
bash install.sh
```

**Сам установщик следует запускать без `sudo`.** Он устанавливает файлы в домашний каталог текущего пользователя и создаёт пользовательский ярлык.

Установщик создаёт на рабочем столе каталог `my-commands-before-3.0.0-ДАТА-ВРЕМЯ-XXXXXX`. В него целиком переносится прежний `~/bin/my-commands`: скрипты, журналы, настройки и резервные копии. Прежний пользовательский ярлык также сохраняется. Таким образом, старые файлы сначала сохраняются на рабочем столе и убираются из действующего расположения, после чего устанавливается чистый комплект.

Режима обновления с объединением файлов нет. В новую установку не копируются прежние `site.conf`, журналы и внешняя диагностика. Для сайта потребуется заново выбрать исходный каталог. При первой установке без старых файлов каталог сохранения может быть пустым. Недоступный или не настроенный рабочий стол останавливает установку до переноса прежних файлов.

Проверки зависимостей и подготовка файлов выполняются до переноса. При ошибке предусмотрена попытка вернуть прежний комплект. Исходники сайта, рабочая копия сайта, архивы проекта и установленные клиенты VPN или Яндекс.Диска не удаляются.

### 4. Запустить меню

Открыть пункт «Мои команды» в меню Linux Mint либо выполнить:

```bash
~/bin/my-commands/menu.sh
```

## Как устроена работа окон

Раздел главного меню открывается двойным щелчком. Другой способ — выделить раздел и нажать **OK**. В подменю выбирается конкретная операция.

После завершения команды терминал показывает код её завершения и приглашение нажать Enter. Нажатие закрывает окно результата и снова открывает **то же подменю команд — экран 2**. Например, после проверки статуса VPN можно сразу выбрать диагностику или другую локацию без повторного открытия раздела.

К главному меню (экрану 1) возвращает пункт «Назад» или крестик подменю. В главном меню первым расположен AdGuard VPN, затем Яндекс.Диск. При появлении главного меню фокус установлен на Exit: Enter завершает программу. Двойной щелчок по разделу и кнопка OK открывают выбранное подменю.

Кнопка Exit и крестик главного окна завершают меню. Пункт «Назад» и крестик подменю возвращают к выбору раздела. При отмене подтверждения соответствующее подменю может остаться открытым.

Для длительной интерактивной команды сначала требуется завершить саму команду. Например, просмотр локальной сборки сайта останавливается сочетанием Ctrl+C; затем Enter закрывает терминал.

Завершение меню прекращает работу его процесса и убирает значок. Самостоятельно запущенные приложения и службы продолжают работу: закрытие меню не отключает VPN, не останавливает Яндекс.Диск и локальный сервер сайта. Для остановки предусмотрены отдельные команды.

## Пример: проверить Яндекс.Диск

1. Открыть раздел «Яндекс.Диск».
2. Выбрать «Статус Яндекс.Диска» для быстрой проверки.
3. При необходимости запустить «Полная диагностика».
4. Просмотреть вывод и код завершения.
5. Нажать Enter для возврата в подменю «Яндекс.Диск».
6. Открыть диагностические отчёты через соответствующий пункт меню.

Отчёты сохраняются в `~/bin/my-commands/logs/yandex`. Общий журнал операций расположен в `~/bin/my-commands/logs/commands.log`. Журнал позволяет восстановить последовательность действий и увидеть, с каким кодом закончилась команда.

## Пример: выбрать направление VPN

В разделе AdGuard VPN предусмотрены Финляндия, Нидерланды, Италия, Испания, Швеция, Австрия, Бельгия, Лондон, Латвия, Польша и США. Также доступны общее подключение, отключение и диагностика.

Перед использованием конкретного направления следует открыть пункт «Доступные локации VPN». Фактическая доступность и принимаемые идентификаторы определяются установленным `adguardvpn-cli` и учётной записью. Если подключение отклонено, необходимо сопоставить идентификатор в скрипте с выводом клиента. Наличие пункта в меню само по себе не подтверждает доступность сервера.

После подключения проверить результат через «Статус VPN». При затруднениях расширенная диагностика помогает сопоставить состояние клиента и сведения о процессе.

## Пример: работать с сайтом АПС

Раздел сайта подготовлен для конкретного проекта Astro `alsibir-expert` из эксплуатационного комплекта. Перед применением к другому проекту требуется проверить совместимость структуры, команд npm и адреса просмотра.

### Выбрать исходники

Открыть «Сайт АПС» → «Выбрать исходный проект» и указать каталог с файлами `package.json`, `astro.config.mjs` и подкаталогом `src`. Если исходники находятся на USB-накопителе, он должен быть подключён.

Выбранный путь записывается в `~/bin/my-commands/site.conf`. Это текстовая настройка, а не исполняемый сценарий.

### Проверить окружение

Выбрать «Проверить окружение сайта». Встроенный сценарий проверяет пути, наличие `rsync`, Node.js и npm. Проверка версии допускает Node.js начиная с 22.12; в сообщениях сценария рекомендуется версия 24. Это требования приложенной реализации, которые следует сопоставлять с зависимостями самого проекта при его обновлении.

### Запустить локальный сервер

Выбрать «Запустить локальный сервер» и подтвердить синхронизацию. Рабочая копия создаётся в `~/.cache/alsibir-expert-linux`. Сервер запускается через пользовательскую службу `aps-site-dev.service` и продолжает работать после закрытия меню.

Пункт «Открыть сайт в браузере» использует адрес `http://localhost:4321/blog/`. Если сервер выбрал другой порт, фактический адрес следует посмотреть в журнале. Состояние, журнал и остановка сервера доступны в этом же разделе.

**После чистой установки путь к исходникам требуется указать заново. Редактировать следует исходный проект.** При синхронизации изменения, внесённые только в рабочую копию, могут быть удалены.

### Собрать сайт и проверить результат

1. Сохранить изменения исходного проекта.
2. Остановить работающий локальный сервер перед операциями, которым требуется та же рабочая копия.
3. Выбрать «Собрать сайт» и дождаться завершения.
4. Проверить код завершения и сообщения сборки.
5. Запустить «Просмотр сборки» для проверки готового результата.
6. По окончании остановить просмотр сочетанием Ctrl+C и закрыть терминал клавишей Enter.

Команды синхронизации, сборки, просмотра и сервер используют блокировку рабочей копии. Если она занята работающим сервером, другую операцию необходимо выполнять после его остановки.

Пункт «Открыть dist для публикации» открывает каталог готовой сборки. Загрузка на хостинг в этой версии не настроена: публикация выполняется отдельно принятым для проекта способом.

### Создать резервную копию

Пункт «Резервная копия исходников» создаёт архив в `~/site-backups`. Из него исключаются `node_modules`, `dist`, `.astro` и `.git`. Такой архив сохраняет исходные файлы, но не историю Git и не полный установленный набор зависимостей.

## Значок списка в трее и панели задач

В комплект входит `menu-icon.svg` — белый список на синем фоне. Он применяется к главному окну, пользовательскому ярлыку и значку в трее.

Значок в трее существует, пока открыто главное меню. Во время выполнения команды это окно закрыто и значок отсутствует; при работе с подменю он также отсутствует, а после возврата в главное меню появляется снова. Окно вывода команды остаётся обычным терминалом и может отображаться со значком терминала.

Для замены изображения:

1. Закрыть меню.
2. Сохранить новый корректный SVG под именем `~/bin/my-commands/menu-icon.svg`.
3. Повторно запустить программу.

Если требуется другое имя или формат PNG, необходимо изменить значение `MENU_ICON` в `menu.sh` и поле `Icon` в `~/.local/share/applications/my-commands.desktop`. Отображение в трее зависит от включённого апплета системного трея Cinnamon. При сохранении старого значка закреплённого приложения следует заново закрепить установленный ярлык.

## Где хранятся файлы

| Путь | Назначение |
| --- | --- |
| `~/bin/my-commands/menu.sh` | Основной исполняемый файл |
| `~/bin/my-commands/menu-icon.svg` | Значок списка |
| `~/.local/share/applications/my-commands.desktop` | Ярлык меню приложений |
| `~/bin/my-commands/site.conf` | Путь к исходному проекту сайта |
| `~/bin/my-commands/logs/commands.log` | Общий журнал |
| `~/bin/my-commands/logs/yandex` | Диагностические отчёты |
| Рабочий стол: `my-commands-before-3.0.0-*` | Полный прежний комплект и ярлык перед чистой установкой |
| `~/.cache/alsibir-expert-linux` | Рабочая копия сайта |
| `~/site-backups` | Архивы исходников сайта |

## Чистая переустановка и возврат прежнего комплекта

При переходе с предыдущего выпуска используется только чистая переустановка: закрыть меню и терминалы его команд, остановить локальный сервер, распаковать новый комплект вне каталога установки и выполнить `bash install.sh`. Старый комплект сохраняется на рабочем столе и не объединяется с новым.

Для ручного возврата закрыть меню, сохранить новый `~/bin/my-commands` в отдельном месте, затем вернуть целиком прежнюю папку `my-commands` из каталога сохранения на рабочем столе в `~/bin/`. Если сохранён прежний ярлык, вернуть его в `~/.local/share/applications/`, заменив новый. Файлы разных версий не смешивать. Автоматического режима обновления нет.

## Проверка после установки

Для первой проверки достаточно открыть главное меню и нажать Enter: оно должно закрыться. Затем повторно запустить программу, открыть раздел двойным щелчком и выполнить безопасную команду просмотра, например «Использование памяти». После Enter должно появиться то же подменю. Для выхода выбрать «Назад» и нажать Enter при фокусе на Exit в главном меню.

Отдельно проверить крестик, кнопку Exit, создание отчёта Яндекс.Диска и фактические локации VPN. Для сайта сначала выбрать исходники и выполнить проверку окружения.

При подготовке версии проверен синтаксис Bash и встроенного Python. Проверка графического поведения, значков и реальных служб на компьютере пользователя остаётся необходимой частью ввода в эксплуатацию.
